# فاتورة SaaS — منصة الفوترة الإلكترونية للمشروعات الصغيرة والمتوسطة

تطبيق SaaS متكامل من مستوى الشركات العالمية، مبني على فرصة سوقية حقيقية في السوق المصري والعربي، يحل مشكلة إلزامية قانونياً (الفوترة الإلكترونية عبر مصلحة الضرائب المصرية)، ويحتوي على نظام مستخدمين، اشتراكات، تجربة مجانية 72 ساعة، لوحة إدارة فائقة، وبنية آمنة وقابلة للتوسع.

## ✅ ما تم تنفيذه (المراحل الثمانية)

### المرحلة الأولى: البحث واكتشاف الفرصة
- سوق الفواتير الإلكترونية في مصر: 64.94 مليون دولار (2025) → 248.86 مليون دولار (2034)، نمو 16.1% سنوياً [IMARC].
- سوق SaaS في مصر: 639.6 مليون دولار (2024)، نمو 20.6% سنوياً [BlueWeave].
- إلزام ضريبي حقيقي: جميع المنشآت التي تتجاوز إيراداتها 250 ألف جنيه سنوياً ملزمة بالفاتورة الإلكترونية عبر مصلحة الضرائب، والفواتير الورقية غير معترف بها ضريبياً منذ 2023.
- سقف إنفاق المنشآت الصغيرة على البرمجيات السحابية: 500–2,000 جنيه شهرياً.

**الفرصة المختارة:** منصة "فاتورة" للفواتير الإلكترونية وإدارة المبيعات للمستقلين وأصحاب المشروعات الصغيرة في مصر.

### المرحلة الثانية: تصميم وبناء المنتج

- دعم اللغة العربية والإنجليزية مع اتجاه RTL للغة العربية.

- نظام صلاحيات وحماية للبيانات.
- لوحة تحكم للمستخدم (فواتير، عملاء، اشتراك، ملف شخصي).

## 🚀 البدء السريع (التثبيت والتشغيل المحلي)

### المتطلبات
- Node.js 18+
- حساب Supabase (قاعدة بيانات PostgreSQL + Auth)
- حساب Vercel للنشر

### 1. استنساخ المشروع وتثبيت التعاميم
```bash
git clone <رابط المستودع>
cd New-app-saas
npm install
```

### 2. إعداد قاعدة بيانات Supabase
أنشئ مشروعاً جديداً في [supabase.com](https://supabase.com)، ثم نفذ محتوى ملف `supabase/schema.sql` في "SQL Editor" داخل لوحة تحكم المشروع. ينشئ السكربت الجداول، سياسات الأمان (RLS)، والبيانات الأولية للخطط.

### 3. متغيرات البيئة
أنشئ ملف `.env` في جذر المشروع بناء على `.env.example`:

```bash
cp .env.example .env
```

ثم عدل القيم:
- `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY`: من إعدادات مشروع Supabase.
- `SUPABASE_SERVICE_ROLE_KEY`: مفتاح الخدمة من Supabase (للعمليات الإدارية موثوقة فقط).
- `ADMIN_EMAIL=ma24469655@gmail.com`
- `ADMIN_PASSWORD_HASH`: هاش bcrypt لكلمة مرور الإدارة (انظر الخطوة التالية).
- `ADMIN_SESSION_SECRET`: سلسلة عشوائية طويلة لتوقيع جلسة الإدارة.
- `WHATSAPP_NUMBER=201148469161`
- `NEXT_PUBLIC_APP_URL`: رابط التطبيق بعد النشر.

### 4. تعيين كلمة مرور الإدارة (آمن)
لا تُكتب كلمة المرور كنص عاري. أنشئ هاش bcrypt عبر السكريبت:

```bash
node scripts/hash-password.js "كلمة-مرور-آمنة جدّاً"
```

انسخ القيمة الناتجة (تبدأ بـ `$2a$12$...`) وضعها في `ADMIN_PASSWORD_HASH` في `.env` وفي لوحة تحكم Vercel عند النشر.

### 5. التشغيل المحلي
```bash
npm run dev
```
يُشغل التطبيق على `http://localhost:3000`.

### 6. البناء للإنتاج
```bash
npm run build
```

**تكاليف التشغيل التقديرية:** استضافة، entretien، دعم عملاء، تسويق (تقدر بـ 20–30% من الإيرادات).
**صافي الربح التقديري:** 40–60% من الإيرادات بعد بلوغ الحجم المستقر.

- **المحفظ:** 1,000 عميل × 150 جنيه = 150 ألف جنيه شهرياً.

> هذه أهداف طموحة تحتاج إلى إثبات عبر اكتساب عملاء حقيقيين، وليست أرباحاً مضمونة.

### استراتيجية اكتساب العملاء
1. **التسويق بالمحتوى:** مقالات وفيديوهات تشرح الفاتورة الإلكترونية ومصلحة الضرائب (كلمة مفتاحية عالية البحث في مصر).
2. **إعلانات ميتا وجوجل:** استهداف أصحاب الأعمال 기록ات ضريبية، تكلفة اكتساب منخفضة في السوق المصري.
3. **المؤثرين:** شراكة مع محاسبين ومُستشاري ضريبة على فيسبوك/تيك توك عند الملاءمة.
4. **برنامج الإحالة:** عمولة لكل عميل يتم إحالته ويقوم بالدفع.
5. **الواتساب:** قناة المبيعات والدعم الأساسية في مصر.
